# מאגר מקומות האירועים הארצי

מאגר עזר להשלמה אוטומטית של "מקום האירוע" ב-VEYA. **לא קטלוג** — אין כאן תיאורים,
מחירים, תמונות או ביקורות; רק העובדות שעוזרות למארגן אירוע למצוא את המקום שלו:
שם, שמות חלופיים, יישוב, אזור, כתובת, סוג מקום, קיבולת (אם פורסמה), טלפון ואתר
(רק מהאתר הרשמי או מ-OSM), קואורדינטות (רק מ-OSM), מקור וסטטוס.

## קבצים

| קובץ | מה זה |
|---|---|
| `venues_il.json` | **קובץ הייבוא.** רשומה לכל מקום ייחודי. זה מה שהשרת קורא. |
| `venues_il.csv` | אותו מידע לעיון ותחזוקה ב-Excel (UTF-8 עם BOM). |
| `duplicates_report.csv` | כל מיזוג שבוצע (`merged`), חשדות שלא מוזגו (`review`), ושמות זהים ביישובים שונים (`info`). |
| `stats.json` | ספירות: לפי ערוץ, מקור, אזור, סוג, איכות מידע, ושדות חסרים. |
| `research/candidates.jsonl` | יומן הממצאים הגולמי מהחיפוש ברשת (append-only). |
| `research/osm_candidates.jsonl` | מקומות מ-OpenStreetMap אחרי סינון. |
| `research/localities.json` | יישובים + קואורדינטות (OSM) — לשיוך יישוב ואזור. |
| `research/manual_merges.json` | החלטות מיזוג/הפרדה ידניות, כל אחת עם נימוק. |
| `research/add.py` · `osm_extract.py` · `build_dataset.py` | הכלים (ראו "איך ממשיכים"). |
| `research/progress.md` | מה נחקר ומה נשאר. |

## שדות הסטטוס — מה הם אומרים ומה לא

- `verification` — **איכות המקור, לא אישור של VEYA:**
  - `verified_sources` — נמצא באתר הרשמי של המקום, או בשני מקורות שונים לפחות.
  - `single_source` — מקור אחד בלבד.
  - `needs_review` — מידע סותר, יישוב לא ודאי, או בלי יישוב.
- `operating_status` — **אף מקום לא מסומן "פעיל"** רק כי יש לו עמוד ברשת:
  - `unknown` — לא נבדק אם פועל (ברירת המחדל).
  - `closed_reported` — מקור דיווח שנסגר → מיובא **מוסתר** (לא מוצע לזוגות).
  - `uncertain` — יש רמז שאולי נסגר.
- `verified` (בטבלת `venues`) נשאר סימון ידני של אדמין VEYA, ולא נוגעים בו בייבוא.

## מקורות ותנאי שימוש

1. **OpenStreetMap** (Overpass API, בשאילתות קטנות עם המתנה בין ניסיונות) — רישיון
   ODbL 1.0. **חובת ייחוס:** מוצגת בתחתית ההשלמה האוטומטית ("חלק מהמידע: © תורמי
   OpenStreetMap"). אם מפיצים את המאגר עצמו החוצה — חלה עליו ODbL.
2. **חיפוש ברשת** לגילוי מקומות לפי עיר/אזור/סוג אירוע. נשמרות עובדות בלבד, עם
   קישור למקור. טלפון נשמר רק מהאתר הרשמי של המקום (בפורטלים רבים יש מספרי
   "מקשר" וירטואליים).
3. **לא נעשה:** סריקה שיטתית/דפדוף של אתר שתנאי השימוש שלו אוסרים העתקה או בניית
   מאגר — דפי זהב (d.co.il, סעיפים 11.1, 13.2), B144, Mit4Mit, ulam.co.il; עקיפת
   בדיקות בוט (data.gov.il, mdas.org.il); נתוני Google Maps/Places (תנאי Google
   אוסרים לשמור אותם). השאלה המשפטית על עובדות מפורטלים — `open-questions.md` #39.

## זיהוי כפילויות (`build_dataset.py`)

מיזוג **אוטומטי** רק כש: אותו מזהה OSM; או אותו שם מנורמל באותו יישוב (בלי מילים
כלליות כמו "אולמי"/"מלון", בלי שם היישוב שבתוך השם, אותיות סופיות/גרשיים מנורמלים);
או אותו אתר רשמי / טלפון **וגם** אותו יישוב ושם דומה (רשתות כמו דן/ישרוטל חולקות
דומיין בין סניפים שונים). **לא ממזגים** רק בגלל שם דומה, ולא שני שמות שונים באותה
כתובת (מתחם עם כמה אולמות) — אלה נכנסים לדוח לבדיקה. החלטה ידנית נרשמת
ב-`manual_merges.json`.

## איך מייבאים

- **ייצור:** אדמין → מאגר אולמות → "מאגר ארצי" → **תצוגה מקדימה** (לא משנה כלום) →
  **ייבוא בפועל**. דורש הרשאת `venues.edit`. נרשם ביומן האדמין.
- **פיתוח:** `python3 scripts/import_venues.py` (תצוגה מקדימה) / `--apply`. הכלי מסרב
  לכתוב למסד מרוחק.
- הייבוא **ניתן לחזרה** (מפתח `import_key`), לא נוגע באולמות שנוספו מאירועים או
  באדמין, לא דורס עריכות אדמין ולא משנה אירועים. פירוט: `app/venue_catalog.py`.

## איך ממשיכים את המחקר

```bash
cd backend/data/venues/research
python3 add.py "תיאור החיפוש" <<'EOF'
@S=https://example.org/list
שם המקום|יישוב|כתובת|סוג|אתר רשמי|קיבולת|@S|הערה|טלפון מאתר רשמי
EOF
cd ../../.. && python3 data/venues/research/build_dataset.py
```

סוגים: `hall garden complex boutique restaurant hotel loft villa conference synagogue community other`.
הערה שמתחילה ב-`CLOSED:` → נסגר; `UNSURE:` → אולי נסגר. הכלי עוצר אם עמודה זזה.

רענון OSM: מריצים את שאילתות Overpass (ראו `osm_extract.py`, `SOURCE_FILES`) לתיקייה
זמנית, ואז `python3 -I osm_extract.py <תיקייה>`.
