# מתנות באשראי — שפה

הפיצ'ר **בנוי במלואו** (מסך המתנה, חישוב העמלה, חשבון קבלת המתנות, פאנל
אדמין). הוא עדיין **לא שוחרר** — הסליקה במצב הדמיה וההעברה לחשבון ידנית.
זה משנה מה מותר להבטיח (§7).

המונחים כאן **מתעדים את מה שכבר נעול בקוד** — `frontend/src/strings/he.ts`
(אזור המתנה) ו-`backend/app/gift.py`. הם לא הצעה חדשה.

---

## 1. מונחי ליבה — נעולים 🔒

| ✓ אומרים | ✗ לא אומרים | למה |
|---|---|---|
| **מתנה** | מתנה כספית · כסף · צ'ק | "מתנה" לבד. מכובד, ולא מדבר על כסף |
| **להעניק מתנה** | לשלוח כסף · לתרום · להעביר | אחיד בכל 8 סוגי האירוע 🔒 |
| **אזור המתנה** | כספת דיגיטלית · ארנק · gateway · סליקה | "כספת" היא שפת ספקים, לא שפת מותג |
| **נותן המתנה** | תורם · משלם · לקוח · שולח | |
| **סכום המתנה** | הסכום · הסכום ששולם | |
| **עמלת שירות** | עמלה · דמי טיפול · fee · תוספת | |
| **ברכה** | הודעה · טקסט · הקדשה · דדיקציה | |
| **פרטי קבלת המתנות** | חשבון בנק · פרטי סליקה · KYC · מוטב | |

> **"להעניק מתנה" לא עובר דרך הלקסיקון.** בניגוד לכל שאר המונחים תלויי-הסוג,
> הניסוח הזה זהה בחתונה, בברית ובאירוע עסקי (החלטת בעלים 2026-08-24).

## 2. העמלה — נאמרת ישר, לא מוסתרת

העמלה **מתווספת** מעל הסכום ומשולמת בידי נותן המתנה. בעלי האירוע מקבלים
את **מלוא** הסכום שהוזן. זו החלטת בעלים, והיא יתרון — לכן היא נאמרת בגלוי,
במסך עצמו, לפני התשלום.

```
✓ "הסכום שיגיע אליהם, בשקלים"
✓ "בעלי האירוע יקבלו את מלוא סכום המתנה שהוזן"
✓ "עמלת שירות (4%)"

✗ "ללא עמלות!"                  ← לא נכון, וגם סימן קריאה
✗ "עמלה מינימלית של רק 4%"      ← "רק" מוזיל את המותג
✗ "עמלה סמלית"                  ← מתנצל. או שאומרים את המספר, או שלא
```

**כלל קשיח:** לעולם אל תכתוב את שיעור העמלה כמספר קשיח בטקסט. הוא מגיע
כפרמטר מהשרת (`giftFeeExplainer(percent)`). מספר מקובע בטקסט הופך לשקר
ביום שהוא משתנה.

## 3. השאלה, לא ההוראה

השדה הראשי במסך שואל **"כמה תרצו שהם יקבלו?"** — לא "הזן סכום". זה לא
ניסוח יפה, זו החלטה: השאלה ממקדת את נותן המתנה במה שמגיע לזוג, ולא במה
שיורד לו מהכרטיס.

```
✓ "כמה תרצו שהם יקבלו?"     ·  "ממי המתנה?"  ·  "כמה מילים מהלב…"
✗ "הזן סכום"  ·  "שם מלא"  ·  "הזן טקסט ברכה"
```

---

## 4. מיקרו-קופי למוזמן

**הכלל העליון: מציעים, לא לוחצים.** מתנה היא בחירה. טקסט שדוחף בה הופך
את VEYA מספק שקט לגובה כספים — וזה סותר את המוצר.

```
✓ "אפשר להעניק מתנה גם מכאן"
✓ "רוצים לצרף ברכה? היא תגיע אליהם יחד עם המתנה"
✓ "המתנה נשלחה"
✓ "התשלום לא עבר"                    ← מה קרה, בלי להאשים

✗ "שכחתם צ'ק? סגרו פינה בקליק"      ← "בקליק" אסור + מתיילד
✗ "מפנקים מהכורסה"                   ← סלנג, לא VEYA
✗ "בלי לרוץ לכספומט בדרך לאירוע"     ← ממציא לחץ שלא היה קיים
✗ "צ'ק בקליק" · "שיק בסטייל"         ← שתי עבירות במשפט אחד
✗ "אל תגיעו בידיים ריקות"            ← מאשים את המוזמן
```

**המוזמן לא חייב כלום.** אין "תזכורת מתנה", אין "עוד לא הענקתם".
זה הקו שלא חוצים.

## 5. חלון המתנה

אזור המתנה נפתח **3 ימים לפני** האירוע ונסגר **בבוקר שאחריו**
(`guest_journey.gift_window_bounds`).

**אל תכתוב את המספרים האלה בטקסט למשתמש.** הם נגזרים מהקוד ומשתנים בו.

```
✓ "אזור המתנה ייפתח לקראת האירוע"
✓ "אזור המתנה נסגר"

✗ "נותרו לכם 48 שעות!"          ← דחיפות מלאכותית
✗ "המתנות ייפתחו 3 ימים לפני"   ← מקבע מספר שחי בקוד
```

## 6. לבעלי האירוע

הזוג רואה מי שלח, כמה, ומה כתב. הטון: **דיווח שקט**, לא חגיגה ולא הנעה.

```
✓ "מתנה אחת התקבלה"  ·  "12 מתנות התקבלו"
✓ "עדיין לא התקבלו מתנות — כאן יופיעו השם, הסכום והברכה"
✓ "המתנות באשראי ייפתחו למוזמנים ברגע שפרטי קבלת המתנות יאושרו"

✗ "הכסף שלכם מחכה"              ← בוטה
✗ "כבר 8,400 ₪ — מרשים!"        ← חוגג כסף
✗ "בלי צ'קים שחוזרים"           ← מאיים, ומזכיר בעיה שאין להם
✗ "בלי להתעסק עם כספת"          ← שפת מתחרים
```

**עמלה שנותן המתנה שילם היא לא עניינו של הזוג.** היא עניין שבין VEYA לנותן
המתנה, והיא לא מוצגת במסך הזוג. אל "תשקף" אותה מתוך רצון לשקיפות.

## 7. מה מותר להבטיח היום 🔒

| בפועל בקוד | מה זה אומר לקופי |
|---|---|
| הסליקה `MockProvider` — הדמיה בלבד | **חובה לומר את זה במפורש**, לא ברמז |
| ההעברה לחשבון `ManualProvider` — אדם ב-VEYA בודק | אל תבטיח "אוטומטי" או "מיידי" |
| `VEYA_GIFT_ENABLED` כבוי כברירת מחדל | הפיצ'ר לא גלוי לכל אירוע |
| "זכאי" ≠ "פעיל" (`gift_eligibility`) | אירוע יכול להיות זכאי ועדיין לא לקבל שקל |

**ניסוח מצב ההדמיה — הכלל הכי חשוב בקובץ הזה:**

> מוזמן שחושב ששילם כשלא שילם — זו תקלה חמורה בהרבה מכפתור מכוער.

```
✓ "מצב בדיקה — לא מתבצע תשלום אמיתי"
✓ "זהו מסך הדמיה לבדיקת התהליך. לא מוזנים פרטי אשראי ולא עובר כסף."
✗ כל ניסוח שמרמז ובכל זאת משאיר ספק
```

**בשיווק:** אל תכתוב "מתנות באשראי" כיכולת פעילה בדף נחיתה עד שהמתג נדלק
והסליקה אמיתית. הבטחת פיצ'ר שלא שוחרר היא הדרך הכי מהירה לשבור אמון.

## 8. הטוקן

`[קישור מתנה]` **הוצא משימוש** — הוא ב-`RETIRED_TOKENS`
(`backend/app/messaging.py`). הטוקן החי הוא `{{gift_link}}`.

אל תחזיר את הישן לתבנית חדשה: הוא ממופה רק כדי שתבניות ותיקות לא יציגו
למוזמן טקסט גולמי.

⚠️ **פער ידוע:** 12 נוסחי "יום האירוע" מזכירים את אפשרות המתנה. כשהקישור
ריק — מנוע הרינדור מוחק את שורת המשתנה, אבל **לא את משפט התיאור שלפניה**.
כלומר המוזמן מקבל הזמנה להעניק מתנה בלי דרך לעשות זאת. לפני שכותבים נוסח
חדש שמזכיר מתנה — ודא שהמשפט כולו יושב על השורה של הטוקן.
